# Microsoft Teams Alert/Report Delivery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a `teams-webhook` managed subscriber protocol mirroring Slack delivery — alerts (alert_evaluator) and report digests (report_generator) POST a Teams MessageCard; the alerts UI offers a Teams option.

**Architecture:** A third protocol branch in the two delivery loops + a Teams MessageCard builder per path + the protocol added to the subscriber allowlist/validation + a UI option. Best-effort delivery (existing failure-recording pattern); no new infra.

**Tech Stack:** Python 3.12 Lambdas (alert_evaluator, report_generator, api/alerts), Next.js 16.

## Global Constraints

- **No `Co-Authored-By: Claude` trailer** in any commit (user rule).
- **Mirror, don't change Slack/PD:** the `slack-webhook` / `pagerduty-events-v2` paths are unchanged; Teams is purely additive (a new `elif`/protocol value).
- **Best-effort delivery:** a non-2xx/exception is recorded to `last_error` and the loop continues — never aborts alert/report processing (existing pattern).
- **MessageCard format:** Teams Incoming Webhook MessageCard (`@type: MessageCard`, `@context: http://schema.org/extensions`, `summary`, `themeColor`, `sections[].facts`, `potentialAction[].OpenUri`). ASCII-safe values; `themeColor` a 6-hex string (no `#`? Teams accepts `RRGGBB` or `#RRGGBB` — use the bare 6-hex, e.g. `"D93F0B"`).
- **`report_generator` gating unchanged:** Teams report delivery only runs when `REPORT_DELIVERY_ENABLED` (the existing gate).
- **Korean UI copy** for the Teams option hint; keep "Microsoft Teams" / URLs as-is.

```python
def _build_teams_payload(rule: dict, latest: float) -> dict:
    """Teams MessageCard mirroring _build_slack_payload — facts + OpenUri deep
    links. MessageCard works with classic Teams Incoming Webhooks."""
    # severity color: reuse whatever _build_slack_payload uses; default warning.
    theme = "D93F0B"  # orange-red; if the rule carries a severity, map it here
    facts = [
        {"name": "Rule", "value": str(rule.get("name", ""))},
        {"name": "Metric", "value": f"`{rule.get('metric_type', '')}`"},
        {"name": "Threshold", "value": f"`{rule.get('comparison', '')} {rule.get('threshold', '')}`"},
        {"name": "Observed", "value": f"`{latest:.2f}`"},
    ]
    card: dict = {
        "@type": "MessageCard",
        "@context": "http://schema.org/extensions",
        "summary": f"DBOps alert: {rule.get('cluster_id', '')}",
        "themeColor": theme,
        "title": f"🚨 DBOps alert · {rule.get('cluster_id', '')}",
        "sections": [{"facts": facts, "markdown": True}],
    }
    # Deep-link buttons only when FRONTEND_URL is set (same condition as Slack).
    actions = []
    for label, path in (("Open timeline", "/timeline"), ("Open dashboard", "/dashboard"), ("Open alerts", "/alerts")):
        uri = _dashboard_url(rule, path)
        if uri:
            actions.append({"@type": "OpenUri", "name": label, "targets": [{"os": "default", "uri": uri}]})
    if actions:
        card["potentialAction"] = actions
    return card
```

(Adapt `theme`/severity to whatever `_build_slack_payload` does — if it color-codes by a `rule["severity"]`, mirror that mapping; `_dashboard_url` returns "" / None when FRONTEND_URL is unset, so the `if uri` guard mirrors Slack's button condition.)
